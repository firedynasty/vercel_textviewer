## Summary
Publish new subtitled videos to the Library dropdown of https://vercel-textviewer.vercel.app/video_transcript_player.html
WITHOUT a git commit/push. All subtitles for every video go in ONE json, uploaded to Dropbox with rclone;
the player reads it by PATH after a Dropbox popup login ("📥 Load from DB" button), so shared-link URLs
are not involved. Single user, so no Vercel API proxy or env var (an earlier api/videolibrary.js +
DROPBOX_VIDEOLIB_URL design was removed). Code committed and pushed 2026-10-31 (commits 718b8958, c76cc0dd).
NOT yet verified: the live Load from DB click-through (see "One-time setup").

## Everyday workflow (a new video is already in video_transcript_player/youtube/<id>/)
    cd ~/Documents/technical/github/vercel_textviewer
    python3 video_transcript_player/workflow/build_library.py --push
No commit, no deploy. Then in the player click "📥 Load from DB" (signs in via popup the first time per
browser session), and choose the video in the "Library…" dropdown. Without --push it only rewrites
public/video_library.json (local test, not committed).

To get a video INTO video_transcript_player/youtube/<id>/ first, see ~/Downloads/workflow_subtitles_whisper.txt
(from_youtube.sh "<url>" -l zh|ko|..., or by hand for an audio file already in ~/Downloads).
Each folder needs *.srt files; .mp3 files are ignored.

Same login pattern as ~/Documents/technical/github/vercel_youtube/public/index.html (loadFromDropboxClipboard,
dropboxSignInPopup).
Dropbox: dropbox:vercel/textviewer/video_library.json (rclone remote `dropbox`).

How build_library.py picks tracks per folder:
  <id>_<xx>_<yy>.srt present -> sub1 = <id>_<xx>.srt, sub2 = <id>_<yy>.srt, lang = xx
  only <id>.srt              -> sub1 only (e.g. 7UDcz1eDz5s)
  otherwise                  -> first .srt alphabetically as sub1
Titles: YouTube oEmbed (no key), falls back to the id offline. To change a title, edit it in
public/video_library.json (existing titles are kept) and run --push.
